## f7cdc3a perf(ios): start the dictation mic before the speech model is ready

```
Holding the mic took about half a second before anything responded: start()
ran every speech setup step (supported-locale lookup, model check, analyzer
format, analyzer start) before activating the audio session and engine, so
the bar's scope stayed flat and no audio was captured until all of it
finished.

Now the mic goes live first, right after the permission check: the session
activates and the engine starts, and start() returns, which moves the
reducer to recording. The speech model loads alongside. DictationInput holds
the audio heard meanwhile (copied, bounded to about two minutes) and hands
it to the analyzer once it starts, so the first words are not clipped.
Letting go while the model is still loading still delivers everything heard:
stop() ends the input and waits for recognition to finish before
finalizing. Setup failures now arrive as the transcript stream's error
rather than from start(). The resolved locale and analyzer format are cached
by prepare(), and an already granted mic permission skips the async request.

Audio session unchanged and confirmed while recording: play-and-record,
mixes with others, Bluetooth HFP off (no hands-free call mode in cars or
headsets), A2DP output allowed, input from the built-in mic.

Measured in the iPhone 17 Pro Max simulator with a temporary probe calling
the live client (not committed): before, the first supported-locale query
alone took ~355 ms ahead of any audio; after, the engine runs ~290 ms after
the press (warm) and the first mic buffer arrives ~390 ms, nearly all of it
AVAudioSession.setActive, which the simulator routes through the Mac's
audio. The speech model cannot load in the simulator, so on-device timings
are not yet verified. OpenCodeTests: 765 passed.
```

## 8bec12f fix(ios): connect to Tailscale servers over plain HTTP

```
Plain-http servers on a tailnet failed with "Couldn't reach the OpenCode
server". Since iOS 17, App Transport Security blocks cleartext loads to IP
addresses unless they are excepted; NSAllowsLocalNetworking covers .local,
unqualified names and private (RFC 1918) addresses, but not Tailscale's
100.64.0.0/10 CGNAT range, so URLSession refused the load (NSURLError -1022).

Info.plist keeps NSAllowsLocalNetworking and adds NSExceptionDomains entries
allowing insecure HTTP loads for 100.64.0.0/10 and Tailscale's IPv6 range
fd7a:115c:a1e0::/48 (CIDR keys are supported from iOS 17; the app targets
18). NSAllowsArbitraryLoads is not used: other public IPs stay blocked.

Manual server entry now treats an address without a scheme, such as
"100.84.220.87:4102" as `opencode serve` prints it, as plain HTTP instead of
failing with "Enter a valid HTTP or HTTPS server URL". An explicit scheme is
kept as typed (AppFeature.withDefaultScheme).

Verified in the iPhone 17 Pro Max simulator against the local V2 server:
- In-app URLSession probe (temporary, not committed): before, 10.0.10.15
  answered 401 and 100.84.220.87 failed with ATS -1022; after, 100.84.220.87
  answers 401, the Tailscale IPv6 address passes ATS (times out only because
  the server listens on IPv4), and 8.8.8.8 is still blocked by ATS.
- UI tests (temporary, not committed): a fresh install paired with a link
  listing only http://100.84.220.87:4102 and opened the connected session
  screen; typing the bare "100.84.220.87:4102" in manual entry reached the
  server ("The server rejected these credentials", no password given).
- New reducer test manualEntryWithoutASchemeConnectsOverHTTP; OpenCodeTests
  766/766 pass, rebased onto the latest main.
```
